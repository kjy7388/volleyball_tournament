실제 Supabase 프로젝트에 SQL을 실행하거나 인증 계정을 생성하지 않았습니다. 아래 결과는 로컬 환경의 검증이며 원격 연결 성공을 의미하지 않습니다.

로직·어댑터·DB 테스트 합계: **68개**. 브라우저는 설치된 Google Chrome을 사용하며 320·375·390·768·1024·1440px에서 주요 화면 가로 넘침을 검사했습니다. PC 홈과 모바일 브래킷의 스크린샷도 확인했습니다. iPhone 크기 검사는 데스크톱 Chrome 뷰포트 검사이며 실제 iOS Safari 하드웨어 검증은 아닙니다.

DB 테스트는 실제 PostgreSQL 엔진 기반 PGlite에 마이그레이션을 적용합니다. Supabase 전용 `auth.users`, `auth.uid()`, `anon`·`authenticated` 역할을 로컬에 구성해 테스트합니다. 브라우저 테스트의 Auth·HTTP 요청은 모의 응답이지만 조회·저장 RPC는 같은 마이그레이션과 RLS가 적용된 로컬 DB에서 실행됩니다. 원격 Supabase로 향하는 테스트 요청은 없습니다. 브라우저 테스트에서 Realtime WebSocket은 차단하고 포커스 복귀·페이지 이동·새로고침 재조회를 확인했습니다. Realtime 구독 등록·해제는 단위 테스트로 확인했습니다.

## 실제 프로젝트에서 미검증

- `bkfluqugazkimgipbrle`에 마이그레이션 적용 및 Data API 스키마 노출
- 실제 Publishable Key의 유효성 및 실제 Auth 이메일·비밀번호 로그인
- 실제 원격 프로젝트의 RLS·grants와 관리자 권한 등록
- 실제 Supabase Realtime 이벤트 전달·재연결
- 실제 서로 다른 기기/네트워크의 공용 데이터 동기화
- 실제 iOS Safari 및 Vercel 배포 후 직접 URL 접근

기존 `.env.local`은 수정하거나 내용을 출력하지 않았으며, 변수 이름·대상 URL 일치·공개 키 형식·Git 제외 상태만 점검했습니다. 형식 점검은 실제 연결 검증이 아닙니다.

## 재실행

권장 Node 22.23.4 환경에서 `npm test`, `npm run build`, `npm run test:e2e`를 실행하세요. 브라우저 테스트는 5174 테스트 서버를 자동 시작·종료하며 실제 `.env.local` 대신 테스트 변수만 사용합니다. 테스트용 데이터는 메모리에만 생성되고 원격 DB·사용자 기본 브라우저·기존 localStorage를 변경하지 않습니다.

원격 검증 순서는 [SUPABASE_SETUP.md](SUPABASE_SETUP.md)를 따르세요. 이번 변경은 로컬 파일에만 있으며 새 Git 커밋·Push·배포는 하지 않았습니다.
